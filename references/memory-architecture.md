## 分层原则

800 章的项目不可能整本进上下文。按四层取用，越近越细：

| 层 | 内容 | 更新时机 |
| --- | --- | --- |
| L1 常驻 | 项目总控、主角人设锁、上限表、禁区、题材规则 | 变更时 |
| L2 卷级 | 当前卷战略、卷末状态快照、上一卷收束摘要 | 每卷 |
| L3 滚动 | 最近 15 到 20 章摘要、支线板、情感弧线、角色矩阵、未兑现伏笔 | 每章 |
| L4 原文 | 上一批末尾 2 到 3 章全文、本章相关旧章片段 | 每批 |

其余全部走检索：按人物名、地名、物品名、伏笔编号定向取片段，不做整本扫描。

## 索引文件

除基础台账外，长篇必须维护这几份可检索索引：

| 文件 | 用途 |
| --- | --- |
| `章节摘要台账.md` | 每章一行：出场人物、关键事件、状态变化、伏笔动态、字数 |
| `支线进度板.md` | 每条线的当前节拍、上次推进章号、停滞计数 |
| `情感弧线.md` | 按人物记情绪状态、触发事件、弧线方向 |
| `角色矩阵.md` | 谁在哪一章见过谁、各自知道什么、信息边界 |
| `资源账本.md` | 物品、货币、资源存量与消耗记录 |
| `质量债务.md` | 已知但暂不修的问题、影响范围、计划处理章节 |

这些文件是审计员的比对基准。缺失时先重建，不要凭正文回忆。

## 单章上下文装配

顺序固定：

1. L1 常驻
2. 当前卷战略与卷末目标
3. 本章写作包
4. 本章在场人物的当前状态与已知信息
5. 最近章摘要
6. 相关未兑现伏笔
7. 上一章结尾原文

只取在场人物，不把全部角色塞进上下文。角色越多这条越关键。

## 信息边界

写作时按角色矩阵约束：角色只能知道自己在场经历过、被明确告知过或有合理推断依据的事。

每章写作包必须显式写四项：读者已知、主角已知、必须隐瞒、只能暗示。四项全空时不开写，先回建筑师层补。

审计时反查：本章是否有人说出不该知道的事，是否有揭露提前。

## 索引重建

每章回灌摘要与状态；每 10 章校验章号连续性与字数统计；每卷末重建全量快照并归档。

跑 `scripts/book_status.py` 做机械校验：字数进度、章号缺口、支线停滞、伏笔逾期。脚本只给线索，判定仍在审计员。
