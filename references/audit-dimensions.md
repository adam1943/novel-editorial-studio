## 严重度定义

| 级别 | 含义 | 处理 |
| --- | --- | --- |
| block | 硬错误或红线，读者会直接发现，或平台会拒 | 必须本轮修掉 |
| warn | 影响体验但不致命 | 本轮尽量修，超额则记质量债务 |
| note | 风格偏好或潜在风险 | 记录，不强制改 |

## 维度清单

按顺序核，从上游到下游。

硬事实层
1. 时间线：日期、时长、行程、并发事件是否自洽
2. 空间与行程：距离与所需时间是否合理
3. 设定冲突：是否违反已确认世界规则
4. 数值与上限：等级、资源、战力是否越过总控上限
5. 资源账本：物品与货币的增减是否有来源
6. 伤病与恢复：伤势是否无理由痊愈

因果与结构层
7. 动机链：关键选择是否有前因
8. 手段可行性：人物是否具备完成该行动的能力
9. 利益链：各方为什么这样做，是否有人在做亏本事
10. 状态变化：本章是否改变信息、权力、关系、资源、风险或决定
11. 场景必要性：本章是否重复上一章的功能
12. 断章落点：章末是否留下继续读的理由
13. 支线停滞：是否有线超期未推进
14. 伏笔状态：本章是否有埋设、提示或兑现，逾期项是否处理

人物层
15. 视角一致性：是否越界进入他人内心
16. 信息越界：角色是否知道不该知道的事
17. OOC：行为是否违反人设锁
18. 配角智力：配角是否为推动剧情降智
19. 工具人化：配角是否只承担功能没有自身目标
20. 台词失真：语气是否符合身份与处境
21. 情感弧线：情绪变化是否有事件支撑

文本层
22. 流水账：是否用交代代替戏
23. 爽点虚化：承诺的兑现是否落到具体场面
24. 词汇疲劳：同一词或意象是否高频复用
25. 段落节奏：段长是否过度均匀
26. 套话密度：模板句与万金油表达的密度
27. 公式化转折：转折是否总用同一句式
28. 列表化叙述：正文是否出现清单式罗列
29. 说明书腔：是否出现分析报告式语言或方法论术语
30. 机械问题：错别字、标点、引号、章号、字数、占位符

合规层
31. 内容红线：见 `platform-compliance.md`
32. 格式规范：章标题、字数、分段、标点是否符合平台要求

## 题材启用

玄幻与仙侠启用全部维度。都市关闭战力与数值相关项，增加年代与常识考据。悬疑恐怖关闭数值项，加强信息控制与氛围递进。言情关闭数值项，加强情感弧线与关系热度。

题材规则写在 `references/genre-rules.md`，项目可在总控里覆盖。

## 输出格式

审计结果落 `审计/第NNN章.audit.json`，结构固定：

```json
{
  "chapter": 128,
  "words": 2643,
  "verdict": "revise",
  "issues": [
    {
      "dim": 16,
      "name": "信息越界",
      "severity": "block",
      "location": "第 3 场，第 2 段",
      "evidence": "他提到城主的密约",
      "why": "角色未在场且无人告知",
      "fix": "改为从守卫口中听到片段传闻"
    }
  ]
}
```

对话式回复时，先给问题表，再给证据，再给最小修正。
