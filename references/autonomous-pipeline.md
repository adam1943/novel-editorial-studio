## 运行档与授权

两个档位，默认人审档。

| 档位 | 触发 | 行为 |
| --- | --- | --- |
| 人审档 | 默认 | 每批交付后等用户确认，改动大的先问 |
| 自动连载档 | 用户明确说自动推进/跑管线/少干预 | 按批自动写审改，只在停机条件触发时找人 |

进入自动连载档前，必须先确认这几项已经落盘：题材、主角人设锁、结局方向、数值/战力上限、禁区、目标总字数、单章字数区间、每批章数。缺任何一项就先补齐，不靠猜。

自动档的授权范围：正文写作、句子级修订、连续性修复、台账回灌、章节合并或拆分。超出范围的改动一律记为待批，不静默执行：改结局、换主视角体系、改世界硬规则、废弃已兑现伏笔、删除已发布章节。

## 角色分工

同一个 agent 内顺序切换，不做角色扮演对话。

| 角色 | 输入 | 输出 | 禁止 |
| --- | --- | --- | --- |
| 雷达 | 题材、平台规则、同类作品结构 | 方向建议、题材规则选择 | 直接改已确认设定 |
| 建筑师 | 总控、卷战略、台账快照 | 卷骨架、章节清单、章节写作包 | 写正文 |
| 写手 | 章节写作包 + 只读世界状态 | 章节正文 | 改设定、改结局、编造未确认事实 |
| 审计员 | 正文 + 写作包 + 台账 + 机检报告 | 分级问题清单 | 静默改稿 |
| 修订者 | 问题清单 | 修订稿 + 修订说明 | 超出授权范围的重构 |
| 合规员 | 正文 + 平台合规基线 | 合规判定与改写建议 | 用规避手段处理红线内容 |
| 记录员 | 定稿正文 | 台账回灌、检查点、质量债务 | 把待批候选写成正史 |

## 单章主链

1. 装配上下文：按 `memory-architecture.md` 的分层预算取上下文，不整本塞。
2. 编译章节写作包：目标、视角、在场人物、时间地点、冲突、必须发生的状态变化、信息控制、本章禁写项、断章落点。
3. 写正文：满足写作包，且至少改变一项状态。
4. 机检：跑 `scripts/novel_audit.py`，拿到结构化findings。
5. 审计：按 `audit-dimensions.md` 逐维度核，机检结果只当证据。
6. 修订：按严重度从上游往下修，block 级必须清零。
7. 合规：按 `platform-compliance.md` 过一遍红线与格式。
8. 回灌：更新章节摘要、支线板、情感弧线、角色矩阵、资源账本、伏笔台账。
9. 检查点：写进度台账，标明下一章入口。

## 质量门与重试

门槛按项目总控配置，默认值：

- block 级问题数 = 0
- warn 级问题数 <= 3
- 单章字数落在配置区间内
- 本章至少一处状态变化被写进台账
- 本章至少推进一条支线或伏笔节拍

重试策略：同一章最多自动修订 3 轮。第 1 轮按问题清单定点修；第 2 轮换写法重写问题场景；第 3 轮回到建筑师层，怀疑写作包本身有问题，重编写作包再写。三轮之后仍不过门，停机报人。

不要用降低门槛的方式让章节通过。门槛调整属于用户决定。

## 停机条件

触发即停，写清停点、已完成范围、失败证据和建议选项：

- 同一章 3 轮修订仍未过门
- 连续 2 章命中同一类 block 问题（说明规则或大纲有系统性问题）
- 需要改结局、主视角体系、世界硬规则或核心人设
- 合规红线无法在不损坏剧情的前提下改写
- 台账与正文出现无法自动裁决的冲突
- 主线可写素材耗尽，需要新的卷战略
- 用户设定的批次上限或字数上限达到

## 批次与检查点

默认每批 5 章，长跑时按“批 -> 卷段 -> 卷”三级收口。每批结束交付：新增章节、修订说明、机检摘要、台账变更、下一批入口、待批候选清单。

每卷结束追加一次卷级复盘：主线推进度、支线停滞、伏笔兑现率、字数进度、重复功能章清单、下一卷战略调整。

检查点必须能独立恢复。恢复只读磁盘，不依赖对话记忆。

## 工件契约

每章落三个东西：正文文件、机检报告、审计与修订记录。

建议路径：

- `正文/第NNN章-标题.md`
- `审计/第NNN章.audit.json`
- `审计/第NNN章.修订说明.md`

机检报告用 `--json` 输出并存档，便于卷级统计和趋势对比。
