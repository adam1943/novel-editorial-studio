# Evolution Loop

After each batch:

- extract new facts
- record repeated corrections
- capture user preferences and banned patterns
- promote recurring fixes into standing rules

## Promote when repeated

If the same correction appears again and again, stop treating it as a one-off comment. Turn it into a project rule, a style note, or a plot constraint.

## Keep reversibility

Label assumptions that can still change. When the user changes direction, overwrite the old rule and log the decision instead of hiding the change.

## Volume retrospective

At the end of each volume, record: main-line progress against the ladder, stalled subplots, foreshadow payoff rate, word count versus target, repeated-function chapters, and the strategy change for the next volume.

Promote what the audit caught twice or more into `项目总控.md` or the genre rule copy, so the next volume does not re-litigate it.

## Quality debt

Not every warn must be fixed in the same batch. Log deferred items in `质量债务.md` with impact and a planned chapter. Clear them at volume boundaries, and never let a block-level item become debt.
