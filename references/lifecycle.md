# Lifecycle

## 1. Creative brief

Capture the one-line promise, genre, POV, tense, target length, and hard constraints.
Exit when the project can be described without ambiguity.

## 2. Project setup

Create the control package and a first checkpoint.
Exit when the work can resume from disk.

## 3. World and cast

Define stable lore, character motives, limits, relationships, and known facts.
Exit when core contradictions are either resolved or explicitly deferred.

## 4. Outline

Build a dual-track structure: what the reader sees and why events happen.
Exit when the next drafting batch is writable.

## 5. Draft batch

Write 3-5 chapters, or the range the user asked for.
Exit when prose, state backfill, and open questions are all recorded.

## 6. Review and repair

Check continuity, causality, knowledge access, voice, structure, and mechanics.
Exit when blocking issues are fixed or logged for approval.

## 7. Evolve

Promote repeated corrections into standing rules and refresh the checkpoint.
Exit when the next batch can start without rebuilding the same context.

## 8. Serialize at scale

For a million-word target, stop treating the book as one pass. Lock volume goals first, detail only the current and next volume, then run batches through the pipeline in `autonomous-pipeline.md`.

Exit criteria per volume: goal reached, irreversible event recorded, foreshadow ledger balanced, no subplot stalled past its limit, word count on track, and a volume retrospective written.
